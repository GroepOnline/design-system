  self-hosted `pr-isolated`+`cf` / `heavy`+`cf`; private ARC target is `company-ci` (canary
  `company-ci-canary`); measured heavy is `company-ci-heavy` (target ARC

  trusted remote-out deploy is scalar `company-deploy`, with exact host or

  billing-block claims are recorded as stale/transitional. ARC live fact is
  CRDs/namespaces present, no controller/listener/runner resources. No live
  apply.
- CI: fix `validate.yml` job-env `runner.temp` parse break from #441 by setting
  `CARGO_TARGET_DIR` in a step instead of job-level `env`.
- CI: non-empty sync commit after merging `main` into `feat/gh-aw-pilot-20260827`
  to re-enqueue `pull_request` validate / merge-gate on PR #321.
- `catalog/ci-lanes.yaml`: assign root husky/lint-staged/prettier tooling
  (`.husky/pre-commit`, `.lintstagedrc`, `.prettierrc`, `.prettierignore`,
  `package.json`) to the `docs_graphs_indexes` lane so schema-catalog-compat

  graphs/indexes, generated skill indexes, and generated Brain clients.

  `verifier_receipt_key`; legacy MCP `ingest_report` defaults to reject

### Changed

- Nested `apps/chefapp` and `control` workflow copies pin the ChefFactory `cf` runner label (hygiene; GitHub only executes root `.github/`).
- ChefFactory GHA jobs require extra runner label `cf` so they pin to
  repo-scoped `cheffactory-pr-isolated` / `cheffactory-heavy` instead of the
  org `pr-isolated` queue (Buildkite stays off this repo).
- Ruleset `main-merge-gate` no longer requires the PR to be up to date with
  `main`. Green `merge-gate` + no conflict is enough to squash (stops the
  behind → admin-merge loop).
- CI lane catalog covers `SECURITY.md` under `docs_graphs_indexes` so a docs-only
  security-policy diff does not unmatched-fail-open.
- `CODEOWNERS` default owner is `@MisterWanted` (OnlineChef flagged archive).
- CI lane catalog covers `.coderabbit.yaml` under `docs_graphs_indexes` so the
  CodeRabbit config from main does not unmatched-fail-open every PR.
- Spelling canonicalized to **ChefFactory** (historical local typo `ChefFactoy` retired in docs/rules; see maintenance note for local path).
- `docs/platform/observability-event-catalog.yaml` is now a pointer, not a second catalog copy.
- Observability catalog schema v2 adds explicit PostHog plane routing,
  projection-specific correlation fields and stricter privacy defaults.
- Runtime mirrors must adopt the expanded forbidden-property set before the new
  agent observability events are activated.
