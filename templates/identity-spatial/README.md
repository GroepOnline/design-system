# ChefGroep identity template

Compose the accepted identity arrival and calm account feedback from
`components.mjs`. These HTML renderers use the existing `tokens.css` and
`product.css`. They have no framework or runtime package dependency.

`index.html`, `states.html` and `account.html` are generated specimens. The arrival works without
JavaScript. The state specimen uses native radios and a retry button to show
loading, empty, error and notice examples; it sends no requests and claims no
account state. Edit `specimen.mjs` or the renderers, then rebuild:

```sh
node scripts/build-identity-template.mjs
node --test tests/identity-components.test.mjs
node scripts/build-identity-template.mjs --check
python3 scripts/verify-identity-template.py --out /home/joep/Code/GroepOnline/design-system/runtime/identity-proof
```

The last command uses the existing lightweight headless renderer and Node 22+
for bounded desktop, phone, reduced-motion and native keyboard checks across all three specimens. It checks
that the primary action fits, arrival ends within 1.2 seconds, busy buttons retain
their dimensions and cannot activate, skip links focus main, and retry returns
focus to the state choice. It also checks validation focus, required-scope form data, disabled account choices and confirmation failure/success/duplicate/Escape behavior. Screenshots and a hashed manifest go to the output
folder. Inspect the screenshots before completing the visual-review chain node.
The design quality hook runs the Node component tests and artifact drift check.

## Composition

```js
import {
  ActionLink, LandingHero, SiteShell,
} from './components.mjs';

const contentHtml = LandingHero({
  eyebrow: 'ChefGroep intern',
  titleLines: ['Jouw plek', 'binnen'],
  emphasis: 'ChefGroep.',
  description: 'Meld je aan om je account te beheren.',
  actionsHtml: ActionLink({ href: '/sign-in', label: 'Aanmelden' }),
});
const pageHtml = SiteShell({
  contentHtml, plane: 'Intern', homeHref: '/',
});
```

Render the returned HTML in the product's document. Use `PageTitle` instead of
`LandingHero` on account routes, keeping one h1. `Portal` is decorative and may
appear once on arrival; it is absent from operational state examples. `Brand`
uses the bundled SVG with intrinsic dimensions and a named home link.

`Button` emits a native button with a reserved activity slot. The consumer binds
its event handler and owns request state. Render `busy: true` while an operation
is pending, retain the label, and expose readable progress through `Loading`.
Use `Failure` with an explicit recovery action, `Empty` for confirmed absence and
`Notice` only for a result established by the product. Replacing a focused control
requires the consumer to restore focus to a surviving control or region.

Text inputs are escaped. Link/image URLs accept HTTP(S) and relative paths;
return-path and destination authorization still belong to the product.
Properties ending in `Html` are trusted composition slots. Pass only renderer
output or product-owned templates, never API content or user-supplied HTML.

## Sources and boundaries

- `tokens.css` owns the shipped palette, typography and focus tokens.
- `product.css` owns the bundled font registrations, auth page/control styling
  and finite motion. A consumer does not need specimen CSS to render the type system.
- `components.mjs` owns reusable HTML; `specimen.css` only frames the examples.
- `component-contracts.json` lists all product contracts and explicitly identifies
  the implemented exports. Every declared component has an implementation; the gate rejects any mismatch.
- `identity-mark.svg` is a generated byte-for-byte copy of
  `extensions/chefgroep/assets/identity-mark.svg`. Edit that canonical vector.
- `fonts/` contains self-hosted licensed fonts. Retain their licenses when copying.

Copy the relevant renderers, CSS, SVG and fonts into a consumer; record source
revision and file hashes. Keep runtime state and routing in the consumer.
The consumer still owns authorization, validation rules, requests and confirmed
state transitions. These renderers and interaction helpers implement presentation
and accessible behavior; they are a template, not an auth SDK.

## Form, permission and operational components

`Navigation` owns named navigation and `aria-current`; `SiteShell` owns the skip
link and main landmark. All three specimens compose the exported navigation.

`Field` associates label, autocomplete, hint and error text. Set `aria-invalid`
through its `error` argument using the product schema, then call
`focusFirstInvalid(form)` from `interactions.mjs`. This helper focuses the first
enabled invalid native field and does not invent validation rules. Product forms
use `novalidate` and retain entered values after failures.

`AccountChoice` takes explicit membership on each option. Only `eligible` options
are selectable; missing or unknown membership is disabled. `PermissionChoice`
keeps required rights checked and includes them once in native `FormData` through
hidden controls. These controls do not confer authorization. The server validates
the selected account and exact scope set independently. Both groups support
pending and error presentation without changing their supplied facts.

`ConnectionRow` and `SessionRow` keep supplied active/expired/revoked/unknown state
separate from a pending attempt or error. A pending revoke does not render as
revoked. Inactive records cannot trigger a revoke. Session current-device state
and the consequence of ending it are explicit inputs. Use list containers as in
`account.html`. `SecurityMethods` renders supplied methods or distinct loading,
unavailable and error states. `Audit` accepts supplied events with timezone-bearing
timestamps and formats them in the requested locale/timezone. It creates no events.

`Confirm` renders an initially closed native dialog. Bind once with
`bindConfirm(dialog, { onConfirm })` from `interactions.mjs`, then call `open()`
from a real trigger. The helper places initial focus on cancel, uses native modal
containment, disables duplicate confirmation and Escape while the returned promise
is pending, and closes only when that promise resolves. Reject with a safe,
user-facing `Error` to retain the dialog and expose the failure. Closing restores
trigger focus. Call `destroy()` on unmount to remove listeners; request cancellation
and mutation truth remain the consumer's responsibility.

`account.html` labels every account, scope, record and audit event as example data.
Its confirmation deliberately rejects a local demonstration promise. No upstream
request is made and no success is fabricated. Static mutation controls remain
disabled until their handlers are attached.
